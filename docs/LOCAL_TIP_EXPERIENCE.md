# 2026-10-29 · 홈과 내 팁 상세 체험

## 이번에 연결한 흐름

홈 → 팁 작성 → AR 터치 배치·드래그 조정 → Cloud 저장 → 선택적으로 지도 탐색 위치 지정 → 글·사진 저장 → AR로 찾기 → 복원된 주황 핀 터치 → 상세 창.

이미 유효한 Cloud 기록이 있으면 작성 화면의 **최근 실험에서 저장한 위치 사용**으로 연결할 수 있다. 기존 수치 비교 화면은 **AR 실험실**에서 계속 사용한다.

이번 화면은 **내가 이 기기에 저장한 팁의 미리보기**다. 서버에 공개된 주변 팁 조회, 다른 사용자의 콘텐츠 전달, 상세 열람 권한 검증을 구현한 것은 아니다. 50m 후보 조회/최대 5개/10m 상세 열람과 위치 정확도·최신성의 서버 판단은 인수인계 정책에 따라 백엔드 연결 단계에 구현해야 한다. 복원 실패·추적 소실 상태의 AR 핀은 숨긴다.

## 데이터와 표시

- 글은 필수, 제목·사진은 선택이다. 제목이 없으면 본문 첫 줄을 사용한다.
- 이번 로컬 체험의 입력 제한: 제목 60자, 본문 2,000자, 사진 1장·입력 20MB 이하, 저장 팁 100개. 최종 서비스 정책을 새로 확정하는 제한은 아니다.
- 사진은 Android 문서 선택 화면에서 사용자가 고른 항목만 읽는다. 전체 앨범 접근 권한이나 새 라이브러리를 추가하지 않았다.
- 사진은 작업 스레드에서 앱 내부 파일로 복사·축소한다. EXIF 회전/반사를 이미지에 반영하고 JPEG로 다시 저장한다. 원본 사진은 변경하지 않으며 원본 EXIF 메타데이터를 복사하지 않는다.
- 사진 선택 취소·가져오기 실패 시 이전 선택과 작성 중 글을 유지한다. 파일을 읽지 못하면 안내 문구를 보여준다.
- 글·사진은 기존 공유용 Cloud JSON에 넣지 않는다. Cloud Anchor 호스팅이 글·사진까지 서버에 저장하는 것은 아니다.
- 앱 재실행 시 저장한 팁을 다시 불러온다. 앱 삭제·데이터 지우기 시 로컬 콘텐츠도 삭제된다.
- 앵커의 예상 수명 1일이 지나면 AR 진입을 막지만 홈에서 글·사진은 계속 열 수 있다. 만료된 앵커를 사용할 수 있다고 표시하지 않는다.
- 지도 위치는 수동 선택한 탐색 좌표다. Cloud localPose를 위도·경도로 취급하거나 사용자 GPS를 정확한 팁 좌표로 바꾸지 않는다.
- 상세 창은 별도 RN Activity 전환 없이 같은 AR Activity에 띄운다. 창을 닫을 때 세션을 새로 만들지 않는다.
- 핀 터치는 최신 투영(500ms 이하), 핀의 화면 영역, 한 손가락의 탭을 검사한다. 핀 밖/드래그/멀티터치/취소/추적 소실/오래된 좌표로 상세를 열지 않는다. 요청 처리 시 GL 스레드와 UI 스레드에서 표시 가능 여부를 다시 확인한다.
- 현재 사진 교체·작성 취소 뒤 사용하지 않는 사본의 정리 및 팁 수정·삭제 기능은 포함하지 않았다.

## 실기기 확인 순서

사용자 일반 PowerShell에서 실행한다. Prepare는 빌드 후 기존 앱 데이터가 유지되는 설치(-r)를 한다. Launch만으로는 새 네이티브 모듈이 설치되지 않는다.

```powershell
cd C:\Users\SSAFY\projects\yeogirok-ar-poc
.\android\validation\check-device.ps1 -Mode Prepare
```

1. 밝은 색 여기록 홈이 표시되는지 확인한다. AR 실험실에서 기존 수치 비교도 열리는지 확인한다.
2. **이곳에 팁 남기기** → 본문 입력 → **최근 실험에서 저장한 위치 사용** 또는 **카메라에서 위치 정하기**. 새 배치에서는 기존 터치·드래그와 저장 품질 조건을 확인한다.
3. 먼저 사진 없이 저장한다. **AR로 찾기**로 진입해 주변을 비춘 뒤, 실제 복원된 주황 핀의 몸통을 누른다.
4. 상세 글이 맞는지, 창을 닫으면 같은 핀이 유지되는지 확인한다. 핀 밖 터치·드래그·두 손가락 입력으로 상세가 열리지 않는지 확인한다.
5. 사진을 첨부한 팁도 저장한다. 세로 사진 방향, 가로 사진 전체 표시, 긴 본문 스크롤, 사진 선택 취소 및 교체를 확인한다.
6. 앱을 종료하고 다시 열어 저장한 글·사진이 남는지 확인한다.
7. 지도 탐색 위치를 연결한 팁에서 미니맵·카메라 방향 화살표·상세 열기를 함께 시험한다. 지도 위치가 없는 팁은 현장에서 바로 Cloud 복원을 시도한다.
8. 추적이 끊겼을 때 핀을 숨기는지, **다시 찾기** 후 상세가 다시 열리는지 확인한다.
9. 다음 날 만료된 앵커의 AR 진입을 막고 글·사진은 남기는지 확인한다. 기기 시계를 변경해 테스트하지 않는다.

문제가 생기면 다음 명령으로 진단 로그를 보관한다. 본문·사진 데이터는 앱 진단 로그에 출력하지 않는다.

```powershell
.\android\validation\check-device.ps1 -Mode Capture
```

별도의 기기 간 공간 복원 성능이나 실제 위치 오차를 새로 검증했다는 주장은 하지 않는다.

## 17:16 재설치 결과와 Metro 복구

프로젝트의 device-20261029-171551-990 실행 기록에서 BUILD SUCCESSFUL(11초)과 adb install의 Success를 확인했다. summary.json도 buildSucceeded=true, installed=true다. 이후 Metro의 JS bundle 요청이 HTTP 500으로 실패하여 launched=false로 종료됐다. 위의 APK 미확인 상태는 이 실행으로 갱신되었지만 실제 홈 화면·핀 상세 동작은 아직 확인되지 않았다.

실행 중이던 Metro 로그에는 Graph._recursivelyCommitModule의 Got unexpected undefined가 남았다. 동일 코드를 새 Metro 프로세스에서 CLI bundle로 처리하면 성공했고, 결과물에 TipHome, TipExperience, openTipPlacement, 기존 CloudValidationPanel이 모두 포함되었다. 이 차이로 기존 Metro 프로세스의 의존성 그래프 상태 문제를 의심한다. 특정 앱 소스 오류나 라이브러리 호환성 문제로 확정하지 않았다.

- check-device.ps1에 -RestartMetro 옵션을 추가했다. /status의 프로젝트 경로, 8081 리스너 PID, 해당 프로젝트의 절대 CLI 경로와 start 명령·포트가 모두 맞을 때만 해당 Metro를 종료하고 --reset-cache로 다시 시작한다.
- 다른 프로젝트 또는 상대경로 등 식별할 수 없는 프로세스는 종료하지 않는다. 이 경우 기존 Metro 터미널에서 직접 Ctrl+C로 종료한 뒤 같은 명령으로 재시도한다.
- HTTP 실패 시 상세 응답을 키 마스킹 후 metro-bundle-error.txt에 저장한다. 새 홈 모듈이 없는 오래된 번들도 거부한다.
- 캐시 초기화 후 첫 bundle은 시간이 걸릴 수 있어 요청 제한 시간을 180초로 조정했다.
- Windows PowerShell 5.1에서 응답 처리·프로세스 식별·스크립트 구문 검사 22개 통과. 새 Metro 프로세스의 Android 개발 bundle 생성 성공. 실제 실행 중인 Metro 재시작 및 앱 재실행 결과는 다음 명령 후 확인해야 한다.

이미 설치한 APK의 SHA-256을 확인한 후 재빌드 없이 이어서 실행한다.

```powershell
.\android\validation\check-device.ps1 -Mode Launch -RestartMetro
```

참고: [Metro 공식 문제 해결 문서의 reset-cache 절차](https://metrobundler.dev/docs/troubleshooting/).
